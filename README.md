# 布鲁斯桌面摆件控制台 V4.0 - 串口通信与指令集技术文档

本文档详细说明了「布鲁斯控制台 V4.0 (上位机)」与「桌面摆件硬件 (下位机/固件)」之间的串口通信协议、指令集定义以及自动化交互逻辑。

## 1. 通信协议基础配置

上位机通过 USB 虚拟串口（CDC）或硬件 UART 与下位机进行异步通信。

- 波特率 (Baud Rate) : 115200 bps (高速串口，确保动画帧和指令的低延迟)
- 数据位 (Data Bits) : 8
- 停止位 (Stop Bits) : 1
- 校验位 (Parity)   : None
- 数据编码         : ASCII / UTF-8 (纯文本字符流)
- 指令结束符       : \n (换行符, 0x0A)


## 2. 指令集详解

所有指令均以纯文本字符串形式发送，并以 \n 结尾。指令集分为三大类：基础控制、文本显示、DLC扩展。

### 2.1 基础互动与动作指令

这些指令用于控制摆件的核心机械结构和基础表情。

[眼球位置]
- 指令格式: ,X{x}Y{y}\n
- 参数范围: x: 0~6, y: 0~4
- 触发方式: 鼠标移动时实时跟随发送
- 固件建议: 映射到舵机或屏幕坐标。,X3Y3\n 为物理/视觉正中心。

[切换表情]
- 指令格式: b\n
- 触发方式: 快捷键 / 状态恢复 / 退出连招
- 固件建议: 切换至下一个预设表情，或恢复默认待机表情。

[显示爱心]
- 指令格式: z\n
- 触发方式: 快捷键触发
- 固件建议: 触发爱心特效动画。

[眨眼动作]
- 指令格式: a\n
- 触发方式: 快捷键 / 随机自动触发
- 固件建议: 执行一次快速闭眼再睁眼的动作。

[空格动作]
- 指令格式: y\n
- 触发方式: 监听键盘 Space 键
- 固件建议: 触发对应空格键的特定动作/音效。

[退格动作]
- 指令格式: w\n
- 触发方式: 监听键盘 Backspace 键
- 固件建议: 触发对应退格键的特定动作。

[回车动作]
- 指令格式: x\n
- 触发方式: 监听键盘 Enter 键
- 固件建议: 触发对应回车键的特定动作。

[嘴巴闭合/上]
- 指令格式: c\n
- 触发方式: 快捷键 / 打字模拟 / 复位
- 注意事项: 需上位机开启“嘴巴控制”开关。

[嘴巴张开/下]
- 指令格式: f\n
- 触发方式: 快捷键 / 打字模拟
- 注意事项: 需上位机开启“嘴巴控制”开关。

[脖子左转]
- 指令格式: k\n
- 触发方式: 快捷键 / 边缘追踪
- 注意事项: 需上位机开启“脖子控制”开关。

[脖子右转]
- 指令格式: l\n
- 触发方式: 快捷键 / 边缘追踪
- 注意事项: 需上位机开启“脖子控制”开关。

[脖子回正]
- 指令格式: n\n
- 触发方式: 快捷键 / 退出游戏模式
- 注意事项: 需上位机开启 DLC 及脖子控制。


### 2.2 字符与文本显示指令 (打字互动)

核心亮点：上位机会全局监听用户的键盘输入，并将打字内容实时发送给下位机。下位机可在其自带的屏幕（如 OLED/LCD）上渲染对应的字符点阵，实现“看着你打字”的互动效果。

[字母与数字显示]
- 指令格式: {A-Z}\n 或 {0-9}\n
- 触发条件: 用户按下键盘上的字母或数字键
- 转换规则: 上位机会自动将小写字母转换为【大写】发送
- 固件处理: 下位机接收到单个字符（如 H\n），从字库中调取对应字符的点阵数据并显示

[缓冲超时字符显示]
- 指令格式: Z\n / M\n / O\n
- 触发条件: 当用户输入 z/momo 但未完全匹配连招，且缓冲超时(0.5s)后
- 固件处理: 作为普通字母发送到屏幕显示，避免吞掉用户的正常输入


### 2.3 DLC 扩展表情与状态指令

以下指令仅在【上位机开启“附加DLC功能”】后才会发送。这些通常是带有状态持续时间的特殊表情。

[昏睡表情] d\n
- 触发: 快捷键 / 输入 zz / 系统关机
- 恢复: 临时触发时 3秒后 自动发送 b\n 恢复默认

[问号表情] e\n
- 触发: 快捷键 / 输入 ?
- 恢复: 临时触发，3秒后 自动发送 b\n 恢复

[跳动爱心] g\n
- 触发: 快捷键 / momo链第3步
- 恢复: 临时触发，5秒后 自动发送 b\n 恢复

[眯眼表情] h\n
- 触发: 快捷键 / momo链第1步
- 恢复: 临时触发，3秒后 自动发送 b\n 恢复

[感叹号表情] i\n
- 触发: 快捷键 / 输入 ! / momo链第2步
- 恢复: 临时触发，3秒后 自动发送 b\n 恢复

[普通眩晕] j\n
- 触发: 快捷键
- 恢复: 临时触发，3秒后 自动发送 b\n 恢复

[蚊香眩晕] m\n
- 触发: 快捷键
- 恢复: 临时触发，3秒后 自动发送 b\n 恢复


## 3. 自动化逻辑与组合序列 (上位机行为)

下位机开发者需要了解上位机的自动化逻辑，以便知道在特定场景下会收到怎样的指令流。

### 3.1 鼠标超时自动居中
- 触发条件: 鼠标指针停止移动超过 2秒
- 发送指令: ,X3Y3\n
- 目的: 防止摆件长时间斜视，自动让眼球回归正前方

### 3.2 打字嘴巴模拟 (Talking Animation)
- 触发条件: 上位机开启“打字互动”功能时，用户按下字母或数字键
- 指令流: 在发送字符显示指令（如 A\n）的同时，以 30ms 节流间隔随机交替发送 c\n (闭嘴) 和 f\n (张嘴)
- 视觉效果: 下位机屏幕显示字符，同时舵机模拟说话时的嘴巴开合

### 3.3 隐藏连招系统 (Combo System)
上位机内置了 0.5秒 的按键缓冲区，用于识别特定的连续输入：

[ZZ 昏睡连招]
- 用户输入: 0.5s内连按 z z
- 指令序列: d\n → (等待3秒) → b\n
- 效果: 摆件闭眼睡觉，3秒后醒来

[momo 连招]
- 用户输入: 依次输入 m o m o
- 指令序列: h\n (眯眼) → (等3s) → i\n (感叹) → (等3s) → g\n (爱心) → (等5s) → b\n
- 效果: 一套完整的复合情绪动画链

[标点触发]
- 用户输入: ? 或 !
- 指令序列: e\n 或 i\n → (等待3秒) → b\n
- 效果: 表现出疑惑或惊讶


### 3.4 状态复位序列
在特定生命周期节点，上位机会发送一组“清理”指令，确保下位机状态归零。

[从游戏保护模式恢复时]
→ c\n (闭嘴)
→ n\n (脖子回正，若开启DLC)

[程序正常关闭/退出时]
→ b\n (恢复表情)
→ ,X3Y3\n (眼球居中)
→ n\n (脖子回正)
→ c\n × 3 (确保嘴巴闭合)
→ d\n (闭眼睡觉)


## 4. 系统级事件响应 (OS Hooks)

上位机监听了 Windows 系统的电源管理广播，实现与电脑系统状态同步的“拟真”效果（需开启DLC）。

- 系统准备睡眠/休眠 (PBT_APMSUSPEND)
  → 发送 d\n (电脑休眠前，摆件先“睡着”)

- 系统准备关机/重启 (WM_QUERYENDSESSION)
  → 发送 d\n (电脑关机前，摆件先“睡着”)


## 5. 上位机底层运行机制 (供二次开发参考)

如果您打算修改 Python 脚本，请注意以下底层机制：

1. 异步发送队列
   - 使用 queue.Queue 管理串口发送，最大容量限制为 512 条指令
   - 防阻塞机制: 当队列满时（例如鼠标移动过快产生大量眼球指令），上位机会丢弃最旧的队列数据，优先保证最新指令的实时性

2. 键盘节流 (Throttling)
   - 全局键盘监听设置了 30ms 的最小触发间隔，防止长按按键时产生指令风暴导致下位机串口缓冲区溢出

3. 多线程架构
   - 主线程负责 GUI (Tkinter/PyQt)
   - 独立的串口读取/写入线程
   - 全局键盘/鼠标 Hook 线程
